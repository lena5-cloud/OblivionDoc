# Локальная проверка OblivionDoc

Эта копия предназначена только для локального тестирования. На обычном компьютере она использует SQLite `obliviondoc_test.db`, игнорирует `DATABASE_URL` и не запускает автоматическую обработку сроков хранения. Это защищает рабочую базу Neon и документы от случайных изменений во время проверки.

## Запуск в Windows PowerShell

Откройте PowerShell в папке распакованного проекта и выполняйте по очереди:

```powershell
py -m venv venv
.\venv\Scripts\python.exe -m pip install -r requirements.txt
.\venv\Scripts\python.exe -m uvicorn backend.main:app --reload
```

Откройте `http://127.0.0.1:8000`. Swagger находится по адресу `http://127.0.0.1:8000/docs`.

Локальная база пустая: зарегистрируйте отдельный тестовый аккаунт. Учётные записи и документы из Neon автоматически не копируются.

## Что можно проверить

1. Регистрацию, вход и выход.
2. Профиль и сведения об организации.
3. Добавление и редактирование тестовых документов.
4. Скачивание тестовых файлов и оба XLSX-экспорта.
5. Страницы «Безопасность» и «Справка».

## Важно про восстановление пароля

В ZIP-архиве нет `.env`, ключей RuSender/Resend или других секретов. Поэтому **сам по себе архив не умеет отправлять письма**. Код восстановления использует переменные окружения почтового провайдера. Кроме того, для локального теста ссылка восстановления по умолчанию ведёт на локальный экземпляр `http://127.0.0.1:8000`, чтобы токен проверялся в той же тестовой базе.

Для проверки доставки в опубликованном приложении используйте форму восстановления на `https://obliviondoc-site.onrender.com` и проверяйте логи backend-службы Render. Не размещайте секреты в коде, ZIP-архиве, GitHub или чате.

## Важно

- Не копируйте сюда реальные документы или персональные данные.
- Не переносите локальный `backend/main.py` в production: в тестовой копии планировщик отключён намеренно.
- Архив не публикует код на Render и не меняет GitHub.
