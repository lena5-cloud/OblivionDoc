# OblivionDoc

**Веб-приложение для управления документами и сроками их хранения.**

OblivionDoc помогает вести электронный реестр документов, хранить файлы, контролировать сроки хранения и автоматически выполнять выбранное действие после истечения срока.

## О проекте

Проект создан как учебный MVP в области информационной безопасности. Пользователь может зарегистрироваться, добавить документ, указать срок хранения и выбрать действие по его окончании — архивирование или удаление. Основные операции отражаются в журнале действий.

## Возможности

- регистрация, вход и выход из аккаунта;
- хранение паролей в виде хешей с использованием scrypt;
- восстановление пароля по электронной почте при настроенном почтовом провайдере;
- добавление, редактирование, скачивание и удаление документов;
- загрузка PDF, DOC, DOCX, TXT, PNG, JPG и JPEG размером до 10 МБ;
- указание срока хранения и действия после его окончания;
- автоматическая обработка документов с истёкшим сроком в развёрнутой версии;
- журнал действий с документами;
- профиль пользователя и сведения об организации;
- экспорт реестра документов и журнала действий в формат XLSX.

## Технологии

**Backend:** Python, FastAPI, SQLAlchemy, Pydantic, APScheduler.

**Frontend:** HTML, CSS, JavaScript.

**Базы данных:** PostgreSQL в развёрнутой версии на Render; отдельная SQLite-база для локальной проверки.

**Дополнительно:** Bearer-токены для авторизации; RuSender API и необязательный Resend API для отправки писем восстановления пароля.

## Локальный запуск в Windows

Откройте PowerShell в корневой папке проекта и выполните команды по очереди:

```powershell
py -m venv venv
.\venv\Scripts\python.exe -m pip install --upgrade pip
.\venv\Scripts\python.exe -m pip install -r requirements.txt
.\venv\Scripts\python.exe -m uvicorn backend.main:app --reload
```

После запуска откройте:

- Приложение: http://127.0.0.1:8000
- Документация API (Swagger): http://127.0.0.1:8000/docs
- Проверка доступности API и базы: http://127.0.0.1:8000/health

При локальном запуске создаётся отдельная база SQLite `obliviondoc_test.db`. Переменная `DATABASE_URL` для локальной копии не используется. Для её переопределения предусмотрена переменная `OBLIVION_TEST_DATABASE_URL`, которая должна указывать на SQLite.

В локальном режиме планировщик сроков хранения отключён, поэтому тестовый запуск не будет автоматически архивировать или удалять документы. База создаётся отдельно; данные из рабочей базы в неё автоматически не переносятся.

## Настройки развёрнутой версии

На Render необходимо задать переменную окружения `DATABASE_URL` для PostgreSQL. Для работы восстановления пароля также требуются корректные настройки почтового провайдера. В зависимости от выбранного сервиса используются переменные `RUSENDER_API_KEY`, `RUSENDER_KEY_ID`, `RUSENDER_FROM` или `OBLIVION_SMTP_FROM`; для необязательного резервного провайдера Resend — `RESEND_API_KEY` и `RESEND_FROM`. Адрес страницы из письма задаётся через `OBLIVION_FRONTEND_URL`.

**Не помещайте в репозиторий реальные ключи, пароли, содержимое файла `.env`, базы данных или пользовательские документы.** Секреты задаются через Environment в настройках сервиса. В локальном режиме значения для почты не задаются автоматически, поэтому отправка писем без конфигурации провайдера работать не будет.

## Миграция данных

Скрипт `migrate_sqlite_to_postgres.py` предназначен для переноса данных из SQLite в PostgreSQL. Запускайте его только при необходимости миграции, после резервного копирования и проверки конфигурации источника и назначения: это не обычная команда для локального старта приложения.

## Статус проекта

OblivionDoc находится в стадии разработки. В MVP реализованы основные сценарии управления документами, контроля сроков, ведения журнала действий и экспорта данных. Перед использованием с реальными документами необходимо отдельно проверить конфигурацию развёртывания, резервное копирование и политики доступа.
